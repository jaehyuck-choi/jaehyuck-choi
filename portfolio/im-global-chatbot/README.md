# iM Global · 체류 연장 안내 챗봇

> 2026 AI Blockchain Challenge in Daegu · 공모주제 ❷ 금융 소외계층을 위한 서비스
> 팀 아이엠그라운드(4인) · 2026.09

iM Global은 외국인 고객을 위한 금융 특화 번역·체류 안내 웹 플랫폼입니다. 금융 용어를 보호하며 번역하는 5개 언어 번역 모듈과 E-9·D-2 체류 안내 챗봇을 한 웹에서 제공하고, 체류정보·만료일 관리 화면을 함께 구성했습니다. 블록체인은 설계 단계로, 향후 은행과 기관 간 서류 검증 이력 공유로 확장하는 계획입니다(과제명 TCB: Translation · Chatbot · Blockchain). 초기 검증 대상은 대구 지역 외국인 근로자와 유학생입니다.

저는 이 중 **체류 연장 안내 챗봇**을 맡았습니다. 어떤 체류자격(E-9 비전문취업, D-2 유학)을 대상으로 할지 데이터로 정하고, 질문 흐름을 설계하고, 웹 데모까지 직접 만들었습니다. 번역 모델과 블록체인 설계는 다른 팀원이 맡았습니다.

## 출발점 · 주짓수 도장에서 들은 질문
챗봇의 방향은 제 경험에서 정했습니다. 주짓수 도장을 다니며 외국인 친구들과 가까워졌는데, 이들이 체류 연장 같은 한국 행정절차를 앞두고 저에게 자주 물어봤습니다. 흥미로운 점은 **"어떤 서류가 필요한지"는 대부분 이미 알고 있었다**는 것입니다. 막히는 지점은 그다음, **"그 서류를 어디서, 어떻게 받느냐"** 였습니다.

그래서 이 챗봇의 목표를 "서류 목록을 알려주는 것"이 아니라 **"사용자가 실제로 서류를 손에 쥘 때까지 안내하는 것"** 으로 잡았습니다.

## 사용자 관점에서 내린 설계 결정
**1. 서류마다 발급 방법까지 직접 정리**
- 모든 서류에 *어디서·어떻게 받는지*를 함께 적었습니다. 예) 재학증명서 → 대학 포털의 증명서 발급 메뉴, 잔고증명서 → 거래은행 앱이나 창구, 통합신청서 → 하이코리아 민원서식, 취업활동기간 연장확인서 → 고용주가 고용노동부에 재고용 신청 후 발급
- 발급 경로를 유형별(본인 보관 / 대학 / 은행 / 고용주 / 정부 서식)로 나누고, 온라인이 안 될 때의 대안과 **"발급일로부터 3개월 이내"** 같은 유효기간 주의사항도 붙였습니다. 친구들이 실제로 되물었던 질문을 미리 답해두려는 의도였습니다.

**2. 마지막 "정리해드릴게요" 화면을 토글로 전환**
- 처음에는 마지막 단계에서 필요한 서류와 발급 방법, 관할기관을 한 번에 길게 보여줬습니다. 그런데 사용자 입장에서 다시 보니, 대화 끝에 긴 글이 한꺼번에 나오면 **읽고 싶지 않고, 읽어도 눈에 잘 들어오지 않았습니다.**
- 그래서 결과를 **항목별 토글(펼침/접힘)** 로 바꿨습니다. 처음에는 제목만 보이고, 필요한 항목만 눌러서 펼쳐보는 방식입니다. 정보량은 그대로 두고 한 번에 읽어야 하는 양만 줄였습니다.

**3. 막히지 않는 대화**
- 외국인은 **본인 상황 자체를 정확히 모를 수 있다**는 전제에서 출발했습니다. 그래서 주요 질문마다 '모르겠어요' 선택지를 따로 만들어, 정보가 부족해도 안내가 끊기지 않고 다음 단계로 이어지게 했습니다.
- 주소는 자동으로 불러오고, 전국 16개 시·도 → **228개 시·군·구를 관할 출입국·외국인관서와 매핑**해서 "관할청에 문의하세요" 대신 정확한 기관명과 연락처를 보여줍니다.

**4. 막다른 길 없는 예외 처리**
- 구직등록 90일 초과, 사업장 변경 횟수 소진처럼 경로가 불확실한 경우에도 "상담원 연결"로 넘기지 않고, 실제 관할청 연락처와 **하이코리아 대표번호(1345, 다국어 상담)** 까지 끝까지 안내합니다.

**5. 틀린 정보를 주지 않기 위한 보수적 설계**
- **수수료**는 금액이 바뀌면 바로 오정보가 되기 때문에, 금액은 표기하지 않고 "수수료가 있다"는 사실과 납부 방법만 안내합니다.
- **신청서 서식**은 자체 사본을 두지 않고 국가법령정보센터(law.go.kr) 원본 링크로 연결하고, 하이코리아 **온라인 신청** 채널도 함께 안내합니다.
- **대학 등급별 규칙**(우수인증·일반·제한 대학에 따른 서류 면제/심사 강화)은 챗봇이 확정 판정하지 않고, 일반 기준을 정확히 안내하는 데서 멈추도록 했습니다. 발표 문구 초안에 "저장된 데이터로 규칙을 자동 적용"이라고 적힌 적이 있는데, 실제 설계와 반대라서 직접 바로잡았습니다.
- E-9의 "구직등록 특례"는 실제 의미가 더 잘 드러나도록 **"구직신청자 대상 특례"** 로 명칭을 정리했습니다.

**6. 화면 문구와 데이터가 어긋나지 않게 검수**
- 대화 흐름은 하나의 규칙 JSON(v1 → v5)에서 관리하고, 데모 HTML은 그 JSON으로 생성했습니다. Playwright로 전체 대화 경로를 끝까지 눌러보는 end-to-end 테스트를 돌렸습니다.
- 문구 검수용 엑셀은 설명이나 JSON에서 따로 옮겨 적지 않고, **실제 챗봇 화면을 자동으로 순회하며 노출되는 문구만 그대로 긁어와** 만들었습니다. 검수 의견은 JSON과 HTML 양쪽에 동시에 반영해서 엑셀·JSON·HTML이 어긋나지 않게 했습니다. 한쪽만 고쳐져 불일치가 생긴 적이 한 번 있었는데, 자체 점검으로 찾아 바로잡았습니다.
- 이렇게 완성한 최종 JSON(v5.0)과 데모를 UI/UX 담당 팀원에게 전달했습니다.

## 기 · 문제
대구 외국인주민은 **61,554명**(2024, 전년 대비 +4.4%)으로, 급여계좌·해외송금처럼 은행과 반복 거래하는 고객군입니다. 그러나 체류기간 연장에 필요한 서류가 체류자격과 상황마다 달라, 고객은 무엇을 준비할지 모르고 은행은 고객정보 갱신 상담 부담을 겪습니다. 그래서 팀은 금융 번역과 체류 안내를 한곳에서 해결하는 플랫폼을 제안했습니다.

## 승 · 체류자격 대상 선정과 대화 설계
- **데이터로 대상 선정:** KOSIS 「시군구별 체류자격별 등록외국인 현황」으로 최근 5년 상위 체류자격을 분석. 연장허가가 필요 없는 영주(F-5)를 제외하고 **비전문취업(E-9)·유학(D-2)** 으로 확정
- **E-9 분기:** 같은 사업장 계속 근무 / 사업장 변경 구직 중 / 모름 → 3년 만기 재고용 여부, 구직등록 90일 이내·사업장 변경 가능 횟수에 따라 연장확인서·구직등록 특례 서류 안내
- **D-2 분기:** 야간·주말 수업 여부(제한 대상 확인), 대학 등급별 서류 면제·심사 강화 규칙 자동 매칭

## 전 · 사용성 문제와 해결
| 문제 | 해결 |
|---|---|
| 사용자가 자기 조건을 몰라 질문에서 막히고 이탈 | 모든 질문에 **'모름' 선택지**. 모르는 경우에도 하이코리아 대표번호 등 별도 안내로 다음 단계 진행 |
| 어느 출입국 기관에 가야 하는지 찾기 어려움 | 저장된 **체류지 주소 자동 로드** → 전국 **228개 시·군·구 관할청 매핑**, 위치·연락처 안내 |
| 서류 목록만으로는 준비가 어려움 | 필요 서류와 **발급기관·방법·절차**까지 단계별 안내 |

## 결 · 결과와 의미
```
체류 만료 임박 알림 → 챗봇 실행 → 가입정보 자동 로드 → 관할기관 자동 연결
→ 재직/구직 상태 확인 → 조건별 연장 규칙 적용 → 필요 서류·관할기관 안내 → 은행 고객정보 갱신 안내
```
- 위 흐름을 웹 프로토타입으로 시연했습니다. 팀 서비스에서는 챗봇 안내가 팀의 금융 특화 번역 모듈을 거쳐 5개 언어로 나갑니다.
- 향후 은행과 연계하면 안내 종료 후 갱신된 체류정보가 은행 고객정보 갱신 안내로 이어지도록 해, 챗봇을 **은행의 고객 유지 접점**으로 삼는 것을 목표로 했습니다
- 다음 단계: 실제 규칙 데이터 연동, 안내 완료율 측정

**다시 만든다면**
- **은행 데이터 연동**: 은행이라는 맥락을 살려, 급여 입금 내역 같은 데이터(마이데이터)로 재직 여부를 미리 파악하면 사용자가 답해야 할 질문 자체를 줄일 수 있습니다.
- **먼저 알려주는 구조**: 지금은 사용자가 챗봇을 열어야 안내가 시작됩니다. 체류 만료가 다가오면 은행 앱이 먼저 알림을 보내는 방식으로 바꾸고 싶습니다.

**배운 점** · 복잡한 행정 규정을 이탈 없는 대화 흐름으로 바꾸려면, 규칙의 정확성만큼 "모를 때 어디로 보낼지"를 설계하는 것이 중요하다는 것을 배웠습니다.
